# linge.xin 前端改进计划

日期：2026-09-07  
基线：`7e4e98d perf: optimize frontend loading and image assets`  
状态：批次 A 已完成本地实现与回归，详见 `frontend-stage-a.md`；尚未部署，B–G 未开始。下文各页面方案仍是完整路线图，不代表全部已经交付。

## 1. 项目定位与目标

界面定位：公开网站以 Explore（浏览）为主，项目案例与文章阅读属于 Decide-Learn（了解与学习），站长工作台属于 Operate（操作）。只有首页承担较强的个人形象展示，不把所有子页面都做成大标题宣传页。

网站需要分别服务三类真实需求：

| 访问者 | 想完成的事 | 推荐路径 |
| --- | --- | --- |
| 初次认识你的访客 | 了解你是谁、关注什么、做过什么 | 首页 → 精选项目 → 项目详情 → 时间线 |
| 查阅知识的读者 | 找到笔记、阅读内容、继续查阅 | 学习笔记 → 搜索或分类 → 正文 → 相邻或相关文章 |
| 站长本人 | 导入、分类、编辑、检查并发布文章 | 站长入口 → 内容列表 → 编辑预览 → 保存或发布 |

本轮目标是提高内容辨识度、浏览效率和阅读舒适度，不是增加功能数量。

### 保留的内容

- 樱花首页、现有绿色品牌色、少量液态玻璃与有目的的动效。
- Vue 3、Element Plus、现有路由和组件体系，不更换前端框架。
- 已验证的教育经历、项目职责、时间和奖项，不改写成未经核实的成绩。
- 公开笔记与站长工作台的权限边界。
- Markdown、Obsidian Callout、数学公式、代码渲染、搜索、分类、阅读位置与相邻文章等现有能力。
- 最近完成的按需加载、响应式 WebP、图片优先级和缓存优化。

### 暂不做的内容

- 恢复 GoalBot、增加聊天机器人、评论系统、点赞计数或社交动态流。
- 全站换色、重画全部页面、增加粒子背景、重型 3D 或滚动劫持。
- 新增完整 CMS、重构数据库或改动后端接口。
- 用装饰图代替项目截图，编造用户量、性能数据、评价或获奖信息。
- 同时引入 SEO 服务端渲染改造；该项单独评估和发布。

## 2. 当前问题与优先级

以下结论来自当前源码与此前首页预览，不代表已经完成新一轮线上全站实测。

| 优先级 | 当前情况 | 用户影响 | 处理方向 |
| --- | --- | --- | --- |
| P0 | 顶部站长入口采用显眼的玻璃按钮，而项目和笔记入口较弱 | 访客容易将管理入口误认为主要入口 | 弱化站长入口，突出公开内容 |
| P0 | 笔记在 1101px 起切三栏，左右栏合计占用较大 | 中屏正文可用宽度约 500px，公式与代码拥挤 | 根据正文最小宽度决定栏数 |
| P1 | 首页展示全部三个公开项目，并提供具体工作展开 | 首页与项目详情的信息重复 | 首页精选两个，完整内容留在详情页 |
| P1 | 首页整图覆盖较重的深色遮罩 | 樱花主体偏灰，明亮主题表达不足 | 先调整构图，再根据对比度调整遮罩 |
| P1 | 项目详情主要是文字和概念流程 | 不容易直接看到实际成果 | 加入经核实、可公开的真实素材 |
| P1 | 时间线含较多解释布局方式的文案 | 访客先读设计说明，后读个人经历 | 保留事实、图例和必要状态，删去自我解释 |
| P1 | 时间线共用详情区位于轨道区域之后 | 选中项目后可能需要寻找更新位置 | 使选择与详情保持空间关联 |
| P2 | 动态背景为全局组件，阅读和后台也会出现 | 长时间阅读与操作时有持续干扰 | 按页面类型限制动效范围 |
| P2 | 关于页悬停会改变内边距，小标签存在 11px 和较大字距 | 内容位置跳动、字体体系不统一 | 固定布局，统一排版规则 |

P0 表示本轮最先处理，不表示发现了安全故障。

## 3. 设计系统：先约束，再实施

### 3.1 色彩

沿用五个基础色，值只允许定义在全局语义 token 中：

| Token | 当前值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f3f0e8` | 页面底色 |
| `--surface` | `#fffdf7` | 正文与工作区实色背景 |
| `--text` | `#1b2721` | 主文字 |
| `--brand` | `#285d4d` | 主要入口、选中状态与结构强调 |
| `--accent` | `#c76d7a` | 少量重点标识，不大面积铺底 |

- 使用现有 `--muted`、`--line`、`--brand-soft` 等派生 token，不在组件里加入裸色值。
- 实色正文区与留白承担主要面积，绿色承担导航和结构，不让整页都泛绿或泛黄。
- 如需提亮底色，仅统一调整现有中性色 token，不再新增色系；同时检查文字、边框和焦点样式。
- 默认不新增渐变；已有玻璃高光只服务于材质，不扩散到正文背景。
- 正常文字对比度目标至少 4.5:1，大字至少 3:1，关键控件边界与状态至少 3:1。
- 半透明区域在实际背景的明暗两端检查，不能只检查 CSS 前景色和透明背景值。
- Callout、代码高亮和 KaTeX 的内容语义样式单独保护，不能为了压缩站点色板把它们全部改成单色。

### 3.2 字体与文字层级

- 网站 UI 保持两套字体栈：展示标题沿用现有宋体风格，正文沿用苹方与系统无衬线回退。
- 宋体只用于首页姓名和少量顶级展示标题；笔记、项目内部标题、表单和工具文字使用正文栈。
- Windows 未安装苹方时使用现有微软雅黑回退，不承诺跨平台逐像素一致，不引入未经授权的字体文件。
- 代码等宽字体和数学公式字体是技术内容渲染依赖，不纳入两套 UI 字族限制，保持原有功能。
- 正文以 16px、行高 1.6 为默认；元信息和辅助文字不低于 14px。
- 子页面主标题建议手机 28–32px、桌面 36–40px；正文小标题按 24/20/18px 逐级递减。
- 首页姓名可保留更大的展示字号，但不得挤压操作入口和下一区块的露出。
- 字距统一为 0；标题使用 `text-wrap: balance`。不使用随视口连续缩放的字号。
- 中英混排、长标题和长链接分别检查；不要用强制截断掩盖布局问题。

### 3.3 布局与控件

- 移动优先，使用现有 4/8/12/16/24/32/48/72px 间距刻度与 `gap`。
- 内容页使用非悬浮的连续区块，不把每一段内容包成卡片，更不嵌套卡片。
- 公开内容宽度通常约 1180–1240px；宽屏笔记容器可沿用 1440px 上限。
- 重复条目和真正需要边界的工具，圆角不超过 8px；浮动导航可保留既有轮廓。
- 交互区域至少 44×44px；图标继续使用 Element Plus 图标库，配套可访问名称和必要 tooltip。
- 不通过改变 padding、宽度、边框厚度或字号实现悬停反馈。
- 路由导航使用链接，展开和切换使用按钮，视图模式使用分段控件，二元设置使用开关或复选框。
- 不把“液态玻璃”“按某快捷键操作”“采用某种布局”等实现说明作为公开页面文案。

### 3.4 玻璃与动效

| 区域 | 保留 | 限制或移除 |
| --- | --- | --- |
| 首页 | 樱花一次轻微进入、少量背景位移、导航玻璃 | 文字跟随鼠标移动、反复播放进入动画 |
| 项目 | 图片查看、章节定位、链接反馈 | 用持续运动替代内容、自动播放演示 |
| 时间线 | 项目轨道一次展开、奖项依次出现、选择反馈 | 强制滚动、等待动画结束才能点选 |
| 笔记 | 目录定位、进度变化、浮动工具玻璃 | 持续背景流动、正文或长侧栏的强玻璃效果 |
| 工作台 | 保存、加载、错误、弹窗等状态反馈 | 装饰背景运动与磁吸按钮 |

- 微交互通常 120–200ms，展开 180–260ms，区块出现 240–360ms；具体以实际观感为准。
- 项目轨道动画不改变真实起止位置，也不通过改变布局宽度制造位移。
- 奖项顺序出现的总等待控制在约 600ms 内；数据多时缩短间隔，不逐条累积长延迟。
- `prefers-reduced-motion: reduce` 下所有内容直接可见、可操作，关闭装饰运动和平滑滚动。
- 不支持 `backdrop-filter` 时使用实色或足够不透明的背景，保证文字可读。
- 玻璃表面的覆盖范围在普通、悬停、焦点状态一致，不能重现“移入才填满边缘”的问题。

## 4. 页面改进方案

### 4.1 全局导航与首页

建议的信息顺序：

```text
站点名称 + 公开导航 + 弱化的站长入口
樱花首屏：姓名 / 身份 / 方向 / 主要入口
精选项目：两个代表项目 + 全部项目
简短个人背景：教育与实践方向 + 时间线入口
学习笔记入口：只介绍内容方向，不展示文章正文
页脚：关于 / 站长入口 / 署名
```

具体任务：

1. 站长入口改为普通低强调链接，保留直达地址，不隐藏必要入口；手机端不让它挤占主导航。
2. 首页“查看项目”为唯一主要行动，“阅读笔记”为次要行动；维持原生链接或锚点语义。
3. 初始精选建议采用“云边端智能识别抓取平台”和“LLM 微信机器人”，体现协作与个人开发；这是编辑推荐，不是对成果大小的认定。
4. 精选使用稳定的项目 ID，不复制项目事实，也不依赖数组偶然排序。
5. 首页项目只保留角色、标题、一句话说明和详情链接，把“具体工作”留在项目详情。
6. 在不破坏既有图片响应式和高优先级加载的前提下调整裁切与遮罩，保证明亮感和文字对比度。
7. 删除重复的技术栈罗列和重复导流，但保留姓名、学校、方向等关键事实。
8. 首屏保留后续内容的提示；短屏可减少上下间距，不把固定高度压到文字重叠。

验收：320px 宽可使用全部导航；站长入口不再是最醒目的行动；两个精选项目均能进入正确详情；全量项目仍在项目页；首页不增加笔记正文 API 或后台资源请求；桌面与手机图片主体可辨认。

### 4.2 笔记列表与阅读页

保留现有搜索、分类、阅读位置、目录、相邻文章和错误重试，重点改善空间分配。

拟采用的响应式规则：

| 可用视口 | 阅读布局 | 分类与目录入口 |
| --- | --- | --- |
| 320–1023px | 单栏正文，居中并限制最大阅读宽度 | 笔记与目录通过现有抽屉打开 |
| 1024–1279px | 正文 + 约 160px 文章目录 | 分类和文章列表通过笔记抽屉打开 |
| 1280px 及以上 | 约 220px 笔记导航 + 正文 + 约 160px 目录 | 两侧显示，正文优先 |

这些是初始断点，不是不可修改的设备分类。按容器实际宽度验算，桌面正文内宽以至少约 640px、通常 640–760px 为目标；达不到时收起一侧。手机不强求该最小值。

具体任务：

1. 分开列表页和阅读页的响应式规则。列表页不预留文章目录空栏。
2. 调整断点时同步处理目录、工具栏、抽屉与回到顶部，防止中间宽度失去分类入口。
3. 当前分类、搜索条件、结果数量和重置入口保持可见，不新增复杂筛选维度。
4. 文章正文保留实色背景，降低侧栏阴影与玻璃强度；长标题完整换行。
5. 代码、宽表格和超长公式只在各自容器内横向滚动，不撑宽整个页面；不通过缩到难以辨认来适配。
6. 保留 Callout 原有图标、折叠与自定义标题，不重新添加用户已要求去掉的默认 NOTE/WARNING 字样。
7. 核对目录点击、浏览器后退、切换分类、阅读位置恢复时的滚动与焦点；标题不能被导航遮住。
8. 手机抽屉支持关闭、Esc 和焦点返回；底部工具避开安全区与回到顶部。

验收：长篇数学笔记、混合中英标题、代码和表格均可读；不存在页面级横向溢出；所有断点都可查找笔记并打开目录；列表失败与正文失败独立呈现；原有 URL 查询参数和阅读恢复行为不变。

### 4.3 项目列表与详情

职责分工：项目列表帮助选择，详情页提供成果证据，时间线只交代时间关系。

详情页建议结构：

```text
项目名称 + 简要目标 + 时间与个人职责
可公开的真实成果素材
问题与约束
本人负责的工作
实现方式与有依据的取舍
现阶段结果、边界与相关笔记
相邻项目 / 时间线定位
```

具体任务：

1. 项目列表保留当前三个公开案例，不把时间线中的网站经历强行变成新的详情页。
2. 每个有素材的项目先选一张最能说明实际状态的截图或一段用户主动播放的短演示，不做自动轮播。
3. 图片预留比例，移动端显示完整重点；细节图可打开可关闭的放大视图，并支持键盘操作。
4. 视频按需加载、提供封面、不默认播放声音；外部演示必须先核实可用性和公开权限。
5. 概念流程图继续明确其性质；未核实的流程不能标为生产架构。
6. 不重复堆技术标签。突出个人职责与系统能力的区别，不把团队成果全部归给个人。
7. 根据真实材料补充结果和局限；没有量化依据时使用可验证事实，不写百分比优化和用户规模。
8. 没有素材的项目维持完整文字案例，不显示空图片框或“正在建设”的装饰区块。

所需素材：可公开截图、演示片段或地址、准确的职责说明。上传前检查姓名、聊天记录、账号、Token、内网地址及他人信息，必要时由用户确认处理后再公开。

验收：每个媒体能说明具体事实，有替代文字、尺寸和加载失败处理；无虚构成果；详情、相关笔记与时间线互相到达；媒体不会显著拖慢首页。

本阶段素材不足时，先做排版和结构，不阻塞其他阶段，也不生成假截图。

### 4.4 时间线

具体任务：

1. 标题直接说明“教育、项目与竞赛”，删除“在同一个坐标里相遇”等不帮助理解履历的包装文案。
2. 删除解释如何绘制界面的段落，保留时间刻度、状态、必要图例及未知日期的诚实表达。
3. 保持实际时间比例、项目并行关系和奖项数据；未知获奖月份仍按类别展示，不推测日期。
4. 宽屏让详情与项目轨道相邻，窄屏在轨道下紧接详情。避免将详情定位到长页面的远处。
5. 点击后同时给出选中轮廓、标题和详情更新，不能仅通过颜色表达状态。
6. 不在每次点击时强制把页面滚到顶；直接链接定位可滚动一次，减少动态时直接到位。
7. 项目轨道一次向右展开，奖项分组轻微依次出现；切换筛选不得重复播放长动画。
8. 手机允许时间图自身横向滚动，同时给出无需横向操作即可读到的选中项目标题、起止时间和职责。

验收：点选后无需寻找详情；键盘可以访问所有条目；缩放和窄屏不遮挡关键内容；轨道长度与状态没有被动画改变；已核实奖项名称、级别、数量及教育时间零变更。

### 4.5 关于页与公共文案

具体任务：

1. 关于页讲真实的学习方向、记录习惯、网站用途与公开联系渠道，不再解释后台发布字段。
2. 不擅自把简历里的私人电话、邮箱或其他资料公开；没有明确确认的联系渠道就不新增。
3. 删除与首页重复的个人简介和反复引导到工作台的入口。
4. 将 11px、小字距标签调整为统一的 14px 和 0 字距，减少无功能的英文编号。
5. 将 hover 的 padding 变化替换为不改变几何尺寸的文字、下划线或背景反馈。
6. 统一各页导航、标题位置、页脚和返回行为，但不为了统一强行抽象所有页面布局。

验收：悬停不导致文字换行或位置跳动；内容仅引用已知事实；联系信息经过确认；不存在面向访客的实现说明。

### 4.6 站长工作台

此项排在公开浏览问题之后，保持操作型界面，不沿用首页的展示式布局。

具体任务：

1. 以文章列表作为新用户的默认管理视图；保留分类看板及已选择的视图偏好，不删除现有操作方式。
2. 将新建、导入、搜索和分类筛选放在稳定区域，刷新改为带 tooltip 的图标工具。
3. 分类字段复用已有分类数据，支持选择现有分类和输入新路径，不新增分类存储模型。
4. 梳理保存、已整理、官网发布三个概念，状态同时有文字，不只用彩色圆点；保持现有后端字段和发布权限。
5. 改动前核对 `published` / `official` 的当前保存行为。若发现必须修改后端才能保证一致，单独记录缺陷和追加范围，不用前端隐藏问题。
6. 手机编辑默认单栏，不强制展示编辑器和预览两栏；保留现有模式切换。
7. 增加本次编辑的未保存变更提示：退出编辑、内部导航时可取消离开；浏览器关闭使用原生允许的提示。此轮不新增自动保存或上传内容副本到其他位置。
8. 明确显示保存中、保存成功和失败状态，失败后保留输入；删除确认的取消行为继续正常结束。

验收：导入 → 分类 → 预览 → 保存 → 发布路径可完成；失败不清空编辑内容；取消删除不发出请求；不因重排表单自动改变公开状态；普通访客不能进入管理接口。

## 8. 验收矩阵

### 8.1 视口与内容

- 手机：320×780、390×844、横屏 844×390。
- 平板和中屏：820×1180、1024×768、1101×800、1280×800。
- 桌面：1440×1000、1920×1080；额外检查 200% 浏览器缩放与布局回流。
- 断点前后各测一个宽度，不只验证整齐的整数设备尺寸。
- 使用真实渲染场景：长标题、无摘要、深分类、重复标题、长公式、宽表格、长代码和无图片文章。
- 有媒体时检查完整加载、慢加载、失败和用户主动播放；浏览器隔离数据不写入真实数据库。

### 8.2 功能与可访问性

- 链接可直接打开和刷新；前进后退保留应有状态。
- 键盘焦点可见，抽屉和图片查看关闭后返回触发元素；无键盘陷阱。
- 不依赖 hover 或颜色才能看到关键信息。
- 加载、空结果、失败与重试分别验证；异步旧请求不能覆盖新选择。
- 搜索条件、相邻文章、阅读位置、数学公式、Callout、代码复制和登录退出保持工作。
- 对照测试减少动态、不支持玻璃滤镜和普通动效三类环境。
- 手工检查实际合成背景上的对比度，不仅依赖静态扫描。

### 8.3 性能与测试

- 执行 `npm run test:unit`、`npm run build`，并根据本批范围运行现有项目与 lazy-UI 浏览器检查。
- 将需要长期复用的笔记布局回归写入仓库 `tests/`，避免仅依赖以前放在临时目录的笔记脚本。
- 性能用生产构建的 preview 测试，不拿 Vite 开发服务器做体积或冷启动结论。
- 继续使用现有首页预算：解压后 JS 小于 250KB，CSS 小于 60KB，实际选择的首屏图小于 350KB，测得 CLS 小于 0.05。
- 与 `docs/frontend-performance.md` 相同的冷缓存、网络、CPU 和视口条件比较；报告多次测试结果，不承诺线上固定加载时间。
- 当前预算只约束首页；项目媒体新增后单独记录该页成本，不把大媒体藏在首页预算之外却全局预加载。
- 首页图片优先级不降低，非首屏媒体按需加载，图片和视频始终预留尺寸。
- 构建警告如仍存在，明确记录，不将“构建通过”等同于无警告。

### 8.4 反 AI slop 检查

实施后逐项打分，1 分表示基本没有该问题，10 分表示问题严重；以下是检查表，不预填虚假的完成分数。

| 项目 | 检查方式 | 命中后的处理 |
| --- | --- | --- |
| 技术感渐变 | 是否由彩色渐变承担主要视觉 | 去掉装饰渐变，恢复图片与实色 |
| 默认靛紫主色 | 是否引入与现有品牌无关的默认色 | 恢复五色语义 token |
| 等权图标卡片阵 | 是否把项目和内容全做成同样方块 | 重排为精选、列表和正文层级 |
| 卡片左侧彩条 | 是否靠彩条装饰而非表达真实语义 | 删除装饰条，不影响代码或引用语义 |
| 无意义玻璃 | 是否长正文和静态区块都使用玻璃 | 只保留必要的浮动表面 |
| 超大数字占位 | 是否用数量代替成果说明 | 删除无用计数，保留事实内容 |
| 圆角图标顶标题 | 是否每段都有无意义的图标底座 | 删除底座，优先标题与间距 |
| 全居中构图 | 是否所有段落和操作都居中 | 根据阅读顺序重排并建立对齐 |
| 默认字体无设计 | 字体是否脱离现有中文体系 | 按展示和正文角色修正 |
| 界面类型错误 | 工作台和阅读页是否变成宣传页 | 按操作与阅读任务重新布局 |

任意项高于 3 分，应修正或记录有内容依据的例外；分数是设计自评，不代替功能测试。
